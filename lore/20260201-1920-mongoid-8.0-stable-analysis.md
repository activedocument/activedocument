### MONGOID-5810 Analysis
The bug occurred only when `Mongoid.legacy_attributes` was enabled, causing `attributes` to return a `BSON::Document` that shared internal state. ActiveDocument removed the `legacy_attributes` feature flag entirely - it always uses the new behavior where `attributes` returns a plain `Hash`. Regression tests were added to `document_spec.rb` to ensure this behavior is maintained.

### MONGOID-5757 Analysis
The fix ensures all associated records are validated (not just stopping at first failure). ActiveDocument already has this fix in `lib/active_document/validatable/associated.rb` using the `map.all?` pattern which evaluates all records.

### MONGOID-5740 Analysis
Performance fix to avoid loading persisted, unchanged associations during validation. ActiveDocument already has this in `lib/active_document/validatable/associated.rb` using the `document.validating do` block pattern.

## Architecture Notes

### Callback Execution Order
The callback execution now follows Rails-compatible patterns:
- Create: `before_save → before_create → [persist] → after_create → after_save`
- Update: `before_save → before_update → [persist] → after_update → after_save`
- Embedded children callbacks execute in proper order via `_active_document_run_child_callbacks`

### Decimal128 Support
- `map_big_decimal_to_decimal128` config option for storage format
- `allow_bson5_decimal128` for BSON 5.0 registry behavior
- Proper numericality validation for Decimal128 values

### Legacy Attributes Removed
ActiveDocument removed the `legacy_attributes` feature flag entirely. The `attributes` method always returns a plain `Hash`, never a `BSON::Document`. This eliminates the class of bugs where internal state could leak through shared references.
